What this means in use
{# Rewritten on 7 Oct 2026: every line here described the one code of the whole instance, which is no longer the way in. A link has its own, and a person reading this was being sent to run a command that does nothing for the link they are actually using. #}

Each link has its own code. It is shown once, when the link is issued under Links over the network, and nowhere afterwards. Lost before the authenticator was set up: take that link back on the same page and issue another — it costs nothing, and no other link is touched.

Then, in a conversation: the assistant hits the lock, asks you for the six digits of that link, and the archive opens. A new conversation asks again; within one it stays open for the window below.

On this machine: {{ cli_root("mcp-lock init") }} sets up a code for the tools used over stdio — the ones started without a link, on this machine. It is not the code of any link, and a link whose own secret has gone missing has no lock rather than this one.

Ending a conversation: ask the assistant to lock the archive. The pass it was given stays written in that conversation, and locking makes it useless to anyone who reads it later.

{# With --data-dir, and said. The first two commands here write to /etc and work from any folder; this one writes a setting of one instance, and its default is a folder called "data" beside wherever the person is standing. Without the option, somebody whose phone was lost was told "The lock is off" while the lock stayed shut over their archive. #}

If you lose the phone with the authenticator: for a link, take it back under Links over the network and issue a new one — a new address and a new code, and nothing of the archive is lost. For the code of this machine, {{ cli }} mcp-lock off --data-dir {{ data_dir }} takes the lock away and {{ cli_root("mcp-lock init --force") }} sets up a new one. The folder has to be named, or the command writes a setting beside wherever you are standing and says it worked.

If the code is refused and you are sure it is right: the clock of this server may have drifted away from the phone's — a machine that stood switched off, a restored snapshot, a time service that did not come up. A code is only good for about half a minute either way. {{ cli }} mcp-lock status --data-dir {{ data_dir }} prints this server's own time to compare with the phone, and a code that is right for a drifted clock is now refused with that said out loud rather than as "the code does not fit".
